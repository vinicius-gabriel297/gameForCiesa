## Project

`Waraná` — 2D pixel-art action platformer (Sateré-Mawé mythology) built for a game jam. Unity **6000.5.7f1**, URP 2D renderer, new Input System, no assembly definitions for game code (everything compiles into `Assembly-CSharp`).

Code, comments and XML docs are written in **Portuguese**, with `Warana.*` namespaces and `AddComponentMenu`/`MenuItem` paths under "Waraná". Match that when editing: comments explain *why* a value or design choice exists, not what the line does.

## Working with the editor

There is no CLI test/lint step — this project is driven through the Unity Editor and the **MCP for Unity** package (`com.coplaydev.unity-mcp`, in `Packages/manifest.json`). Prefer the `mcp__UnityMCP__*` tools and the `unity-mcp-skill` skill over shelling out:

- Read editor state via resources (`mcpforunity://editor/state`, `mcpforunity://project/info`) before mutating.
- `manage_scene` / `manage_gameobject` / `manage_prefabs` for scene work; `read_console` after script changes to catch compile errors.
- `com.unity.test-framework` is installed but **no test assemblies or tests exist**. `run_tests` will find nothing; don't claim a change is "tested" on that basis.

### Editor menu tooling (`Assets/Editor/`)

Scenes and animation assets are **generated by idempotent editor scripts**, not hand-built — regenerating is the intended way to change them, and hand edits to generated assets get overwritten. Menu entries under `Waraná/`:

- `Pixel Art/Configurar Projeto` — disables MSAA/aniso across quality levels, sets up the Pixel Perfect camera. `Pixel Art/Reaplicar Import Settings` reapplies texture rules.
- `Animação/Gerar Clips e Animator` (Piatã), `Gerar Mad Ghost`, `Gerar Abomination`, `Gerar Catto` — rebuild `AnimationClip`s + `AnimatorController` from the PNG frame folders in `Assets/Animations/`.
- `Tilemap/Gerar Tiles e Palettes`, `Tilemap/Build Fase 01 (Floresta)`, `Tilemap/Build Mapa de Teste`.
- `Inimigos/Gerar Prefab do Mad Ghost`, `Gerar Prefab da Abomination`.

Project-wide pixel-art constants live in `Assets/Editor/PixelArt/PixelArtTextureDefaults.cs`: **PPU 64**, reference resolution **640×360**, and import rules apply only under `Assets/Art` and `Assets/Animations`.

## Scenes and flow

Build settings order: `MainMenu` → `Prologo` → `Mapa_01` (`Assets/Scenes/`). `scene_claude`, `TextScene`, and the tilemap greybox scenes are scratch and not shipped.

`MainMenu` (start/options/controls) → `Prologo` (scripted cutscene, `PrologueController`) → `Mapa_01` (the actual level: `LevelIntroController` opening, Mad Ghost enemies, `BossEncounter` with the Abomination, then back to `MainMenu`).

`ScreenFader.Get()` is the single transition path between scenes — it builds its own `DontDestroyOnLoad` canvas on first use, so no scene has to pre-wire a fade panel.

## Architecture

Namespaces map 1:1 to folders under `Assets/Scripts/`.

**Input** — `PlayerInputHandler` (`[DefaultExecutionOrder(-100)]`) is the only script that touches `InputAction`/bindings; it reads the project-wide asset `Assets/Settings/InputSystem_Actions.inputactions` (map "Player": Move/Jump/Attack/Channel) and exposes plain bools/floats. It also owns the cutscene restrictions `SetForwardOnly` and `SetChannelLocked`. UI that must work while the Player map is disabled (`PauseMenuController`, `SkipControl`) creates its own `InputAction` instead.

`Assets/Scripts/UI/GameControls.cs` is the single source of truth for control text (level intro overlay, menu panel, store page). Change a binding in the `.inputactions` asset → update this file.

**Player** — `PlayerController2D` owns movement: `gravityScale = 0` with hand-rolled gravity (rise/fall/low-jump multipliers), coyote time, jump buffer, `FreezeControl` and `ApplyKnockback`. It discovers `PlayerAbility` components via `GetComponents` in `Awake` and sorts them by `Priority`, so **new abilities plug in by adding a component — never by editing the controller**. Existing abilities: `PlayerChannel` (priority 5), `PlayerAttack` (10). `OverridesMovement == false` means the ability lets the controller keep applying gravity/collision and freezes movement through `FreezeControl` instead.

`PlayerAnimator` only reads state and writes Animator params — no gameplay decisions. Param/state names live in `WaranaAnimation` and are shared with the editor animation builder so the two can't drift.

**Combat** — `IDamageable.TakeDamage(amount, point, direction)` is the only contract attackers know. `Health` implements it plus flash/i-frames/knockback, and exposes `Changed` (any value change, incl. heal and `OnEnable`) vs `Damaged` (real damage only) — HUDs listen to the first, hurt reactions to the second. Anything that drives its own `Rigidbody2D` must implement `IKnockbackReceiver`, or `Health`'s velocity write gets stomped the next `FixedUpdate`.

The weapon is `SpiritBoltEmitter` on the **Guaraná orb**, not on the player: while `PlayerChannel.IsChanneling`, it cone-searches for the nearest enemy and fires hitscan bolts, spending `BoltCharges` (3 slots, recharge only outside channeling).

**Enemies** — `EnemyController2D` is the AI-side twin of `PlayerController2D` (manual gravity, wall/ledge probes). It **never flips the transform** — flipping would mirror colliders and probes; only the `SpriteRenderer` flips, in the `*Animator` components. `EnemySenses2D` isolates perception (sight cone, LOS, memory timeout) from the state machines in `MadGhost` (patrol/chase/three-phase attack) and `Abomination` (the boss).

**Layers/tags** — layer 8 `Ground`, layer 9 `Enemy`; the player is found by tag `Player` in several `Start()` fallbacks (`EnemyKillTracker`, `EnemySenses2D`, …).

**Menus are wired in code, not the Inspector.** `MainMenuController` and `PauseMenuController` attach listeners (and `targetGraphic`) in `Awake` and build their panels at runtime, because `UnityEvent` references serialized in a scene don't survive the automated scene rebuilds this project relies on. Keep that pattern.

`MasterVolume` (static, `[RuntimeInitializeOnLoadMethod]`) owns `AudioListener.volume` + its `PlayerPrefs` key; per-sound gain stays on the `AudioSource`.

## Repo conventions

- Build output (`Build_Jam/`, `Wanará/`, `Data/`) and `Assets/Screenshots/` are gitignored; `.csproj`/`.slnx` at the root are generated and ignored too.
- Third-party art/VFX/audio packages sit directly under `Assets/` (JMO Cartoon FX, Legacy_Fantasy, Vefects, Pixel_HUD_UI_FreeKit, …) — leave them alone; only `Assets/Scripts` and `Assets/Editor` are project code.
- Commit messages are short imperative one-liners, mixed PT/EN, no ASCII-only constraint on file names (`Assets/Animations/Piatã`).
- Generated animation assets keep the legacy `Warana_` prefix even though the character was renamed to Piatã — renaming them would break scene GUID references.
